# Security policy

TokenScope is local-first. It reads only configured session roots and extracts usage metadata; it does not access auth files, send cloud telemetry, or collect prompt/response text. Source logs may contain sensitive data: parsed content is transiently in memory and must not be logged. Project basename and session/model identifiers remain personal metadata; review exports before sharing.

Default API binds localhost, requires a generated bearer token, rejects arbitrary Host/Origin headers, and authenticates WebSocket first frames. Token files and databases use restricted permissions where OS supports them. Do not expose standalone mode to a public network. Explicit [server mode](docs/server.md) adds per-account authentication and device ingestion for a trusted team behind a configured HTTPS reverse proxy; public SaaS, multi-process scaling and provider billing attestation are outside this milestone. Directory permissions on Windows depend on inherited ACLs; review user profile ACLs.

Report vulnerabilities privately through the repository's Security Advisory page: https://github.com/IAbuElRuzz/TokenScope/security/advisories/new . Do not include credentials or private logs in public issues. Only the latest 0.1.x source receives fixes. Dependencies must be reviewed before a production release; see validation limitations.


Server mode deliberately transmits metadata only after device enrollment and explicit HTTPS configuration. Device tokens and browser sessions are separate opaque random secrets persisted as hashes. Browser cookies are HttpOnly/Secure/SameSite=Strict; mutations check Origin and a session-bound CSRF token. Passwords use individually salted PBKDF2-HMAC-SHA256 (600,000 rounds); local admins provision/reset accounts without password argv. Role-gated administration exposes account aggregates, while each usage ledger, tombstone scope and stream is private to its account. Server mode never scans host CLI logs. Filesystem operators/backups can read all partitions, and a device may fabricate its own metadata; no invoice authenticity is implied. Configure TLS, proxy limits, private data-directory ACLs and backup policy before remote use.
